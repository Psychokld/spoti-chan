# Spoti-Chan

Учебный музыкальный сервис с будущими ИИ-рекомендациями и AI Music Finder — поиском песен по описанию.

Первый этап: небольшой backend на **Node.js + Express**. Есть каталог из четырёх треков и прототип поиска по жанрам, исполнителям и типу вокала. Это поиск по правилам, **не подключённый ИИ**. API возвращает `mode: "demo-tags"`.

## Запуск

Нужны Node.js 22+ и npm.

```sh
npm install
npm start
```

Сервер: `http://localhost:3001`. Порт можно изменить переменной `PORT`.
`npm run dev` — перезапуск при изменениях, `npm test` — проверка HTTP API.

## API

- `GET /api/health` — проверка сервера.
- `GET /api/tracks` — демонстрационный каталог (только метаданные, без аудио).
- `POST /api/finder` — JSON с полем `description` от 1 до 500 символов.

Пример тела запроса:

```json
{ "description": "Что-то похожее на Linkin Park, но с женским вокалом" }
```

Результат: Going Under — Evanescence, затем Ice Queen — Within Temptation. Каждый трек содержит `matchedTags`, объясняющие совпадение. Женский/мужской вокал используется как фильтр.

Пока распознаются четыре исполнителя из каталога, жанры rock/рок, metal/метал, alternative/альтернативный, symphonic/симфонический, pop/поп, funk/фанк, dance/танцевальный, energetic/энергичный и female/женский, male/мужской вокал. Неизвестный запрос возвращает пустой список. Сложные фразы, отрицания и смешанный вокал пока не поддерживаются.

## Следующие небольшие этапы

1. Интерфейс React + Tailwind CSS: каталог и форма поиска через HTTP.
2. Jamendo API: доступные треки и воспроизведение.
3. Gemini API на backend: извлечение жанров и тегов из свободного описания и подбор по каталогу.
4. Firestore: хранение треков и предпочтений, рекомендации.
5. Firebase Hosting для frontend и Cloud Run для backend.

Ключи внешних API должны храниться на сервере в переменных окружения. На текущем этапе ключи и облачные сервисы не нужны.
