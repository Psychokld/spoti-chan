# Spoti-Chan · v0.3

Музыкальное веб-приложение: React + Tailwind/Vite, Express и SQLite. Хромовый интерфейс с артами пользователя, каталог, Music Finder, рекомендации, избранное и аккаунты.

## Локальный запуск

Нужны **Node.js 24+ и npm**. Из папки проекта:

```sh
npm ci
npm run build
npm start
```

Открыть http://localhost:3001. `npm run dev` запускает API и Vite (http://127.0.0.1:5173). `npm test` запускает автоматические проверки. Для готовой локальной копии с установленными зависимостями и сборкой есть `start-local.cmd` — двойной щелчок запускает сервер. Системный Node.js предпочтителен; скрипт также умеет использовать существующий runtime Codex на этом компьютере.

Настройки можно записать в `.env` по образцу `.env.example`. Сервер сам читает `.env`. Не коммитьте секреты.

## Что работает

- Регистрация и активация через одноразовую ссылку на почту (24 часа). Неактивный аккаунт не входит.
- JWT в HttpOnly/SameSite=Strict cookie (2 часа), отзыв сеансов при выходе и изменении защиты.
- CRUD своего пользователя: создание при регистрации, чтение, изменение имени/почты/пароля, удаление. Чужие профили недоступны.
- TOTP 2FA: QR, подтверждение настройки, второй шаг входа, выключение, одноразовые резервные коды. Повторное использование TOTP отклоняется.
- Пользователи, хеши паролей, сессии и избранное хранятся в SQLite. Пароли хешируются scrypt, TOTP-секреты шифруются AES-256-GCM.
- Избранное гостя остаётся в localStorage; после входа используется отдельная коллекция аккаунта в базе.
- Каталог, жанровый фильтр, поиск по загруженным названию/исполнителю, Finder по описанию, рекомендации по тегам избранного.
- Интеграция Jamendo: реальные аудиотреки, плеер с Play/Pause, прогрессом, громкостью, переходом дальше и ссылками на источник/лицензию.
- Интеграция Gemini: извлечение жанров, вокала, исключений и похожего исполнителя; выдаются только существующие записи каталога, а не придуманные моделью треки.

## Почта и Gmail

**Без SMTP** действует только локальный режим: письмо сохраняется в `.data/outbox/*.json`, настоящей отправки нет. Открой последний файл на своём компьютере и перейди по ссылке из `text`; затем нажми «Подтвердить почту». Папка не публикуется через HTTP и исключена из Git. Удаляйте тестовые письма после проверки.

**С SMTP** задайте `SMTP_HOST`, `SMTP_PORT`, `SMTP_USER`, `SMTP_PASS`, `SMTP_FROM` и правильный `APP_URL`. Получателем может быть Gmail или другая почта. Для отправки через Gmail обычно используются `smtp.gmail.com`, порт `465` и пароль приложения, если он разрешён для аккаунта. Обычный пароль Gmail в проект не вводите; альтернативой является отдельный SMTP-провайдер. См. [Nodemailer/Gmail](https://nodemailer.com/usage/using-gmail/).

Production отказывается запускаться без HTTPS APP_URL, SMTP_HOST/SMTP_FROM и явно заданных секретов. Сбой отправки не активирует аккаунт; есть повторная отправка ссылки. Смена почты требует новой активации даже при ошибке SMTP.

## Музыка и ИИ

В `.env`:

```dotenv
JAMENDO_CLIENT_ID=YOUR_CLIENT_ID
GEMINI_API_KEY=YOUR_API_KEY
GEMINI_MODEL=gemini-3.8-flash
```

Без `JAMENDO_CLIENT_ID` остаются четыре демонстрационные записи без аудио. Без `GEMINI_API_KEY` Finder использует честно обозначенные правила и теги. Любую интеграцию можно включить отдельно. Наличие ключа не гарантирует квоту, доступность модели или музыкального сервиса; ошибки показываются пользователю, без подмены результатами демо.

Jamendo содержит собственный каталог независимой музыки: наличие в нём песен Linkin Park/Evanescence не предполагается. Исходные названия демокаталога не являются лицензией на их аудио. Персонажи на карточках — декоративные арты пользователя, не изображения исполнителей и не официальные обложки.

Текущий список каталога — до 40 записей, кэш 60 секунд. Finder запрашивает Jamendo отдельно. Избранное может содержать до 500 идентификаторов, рекомендации учитывают первые 100 и возвращают до 8 совпадений. Рекомендации ранжируются по тегам; это не обученная персональная модель.

## API

| Метод | Назначение |
| --- | --- |
| GET `/api/health`, `/api/status` | Работоспособность и режимы интеграций без секретов |
| GET `/api/tracks` | Каталог; `?ids=1,2` загружает выбранные записи |
| POST `/api/finder` | `{description}`: 1–500 символов |
| POST `/api/recommendations` | `{trackIds}`: до 100 ID |
| POST `/api/auth/register` | `{displayName,email,password}`: пароль 12–128 символов |
| POST `/api/auth/verify-email` | `{token}` из письма |
| POST `/api/auth/resend-verification` | `{email}` |
| POST `/api/auth/login` | `{email,password}` → user либо challengeToken |
| POST `/api/auth/2fa/login` | `{challengeToken,code}` |
| POST `/api/auth/logout` | Завершить текущий сеанс |
| GET/PATCH/DELETE `/api/users/me` | Собственный профиль; чувствительные действия требуют currentPassword и code при 2FA |
| GET/PUT `/api/users/me/favorites` | `{trackIds}` в базе пользователя |
| POST `/api/auth/2fa/setup` | `{currentPassword}` → secret + QR |
| POST `/api/auth/2fa/enable` | `{code}` → user + 8 recoveryCodes |
| POST `/api/auth/2fa/disable`, `/api/auth/2fa/recovery-codes` | `{currentPassword,code}` |

Изменяющие запросы используют JSON и проверку Origin. Ошибки возвращают `{error}`. JWT/2FA challenge имеют разные audience. Настройка TOTP истекает за 10 минут, login challenge — за 5 минут и 5 попыток. Новый код приложения меняется каждые 30 секунд; после настройки дождитесь следующего кода для следующего действия. Лимиты авторизации и поиска действуют в одном процессе; production рассчитан на одну VM.

## Развёртывание и сдача

- [Техническое задание](docs/TZ.md)
- [Соответствие 7 требованиям](docs/REQUIREMENTS.md)
- [IaaS: Google Compute Engine VM + Docker + Caddy HTTPS](docs/DEPLOYMENT.md)

Конфигурация IaaS подготовлена. **Облачная VM и публичный сайт ещё не созданы**, доставка настоящих писем и живые внешние API требуют настроек владельца. Docker отсутствовал в среде разработки: образ надо проверить на VM командой `docker compose ... build` по инструкции.

Данные разработки: `.data/` (SQLite, случайные локальные секреты, тестовые письма), всё исключено из Git. Не удаляйте ключ шифрования отдельно от базы: старые TOTP-секреты станут недоступны. Для production задайте случайные `JWT_SECRET` (32+ символа) и `DATA_ENCRYPTION_KEY` (64 hex), сохраняйте их вместе с резервной копией БД. Масштабирование, SSO Google, SMS, сброс забытого пароля и административная панель не входят в эту версию.
