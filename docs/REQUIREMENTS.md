# Соответствие требованиям преподавателя

Версия 0.3, 31.10.2026. Эта таблица различает реализованный код и внешнее подключение, которое ещё нужно выполнить. Пароли и адреса с фотографии доски не включены в проект.

| № | Требование простыми словами | Реализация и как показать |
| --- | --- | --- |
| 1 | Регистрация, вход с JWT и активация письмом | `server/auth/index.js`, экран «Аккаунт». Зарегистрировать почту → открыть одноразовую ссылку → подтвердить → войти. JWT находится в HttpOnly cookie, срок 2 часа. До подтверждения вход запрещён. Для настоящего письма на Gmail нужен настроенный SMTP; локальный outbox — только проверка, не доказательство доставки. |
| 2 | API умеет создавать, читать, менять и удалять данные пользователя | POST `/api/auth/register` создаёт пользователя. GET/PATCH/DELETE `/api/users/me` работают только со своим профилем. Показать изменение имени, затем удаление тестового аккаунта. Серверное избранное: GET/PUT `/api/users/me/favorites`. |
| 3 | Размещение на арендованной облачной виртуальной машине — IaaS | Готовы Dockerfile, Compose, HTTPS Caddy и скрипты Google Compute Engine. **Фактическое размещение пока не выполнено.** Для зачёта этого пункта нужны созданная VM в аккаунте владельца, внешний IP/домен, открывающийся публичный сайт и проверка persistence. См. DEPLOYMENT.md. Одного localhost или конфигурационных файлов недостаточно. |
| 4 | Backend на веб-фреймворке | Node.js 24 + Express. Показать `/api/health`, каталог, Finder, аккаунты, middleware и тесты. |
| 5 | Frontend на современном JS-фреймворке | React + Vite + Tailwind, страницы каталога/Finder/избранного/аккаунта, формы и плеер. |
| 6 | Второй фактор при входе | TOTP (Google/Microsoft Authenticator и совместимые приложения), QR, проверка первого кода, отдельный шаг входа после пароля, отклонение повторного кода, одноразовые резервные коды. Показать включение на тестовом аккаунте и последующий вход. |
| 7 | Данные пользователей в базе | SQLite с таблицами users, sessions, login_challenges, recovery_codes, favorites. Это полноценная SQL-база; PostgreSQL/MySQL/MongoDB в исходном списке указаны как примеры. Если преподаватель требует именно одну из них, потребуется отдельная миграция. Показать сохранение пользователя и избранного после перезапуска. |

## Что уже проверено автоматически

`npm test`: HTTP API, активация и её срок/одноразовость, запрет неактивного входа, CRUD только своего профиля, отзыв сессий, TOTP и replay, резервные коды, лимиты, смена почты и ошибка доставки, защита Origin/формат JSON, правила Finder, адаптеры Jamendo/Gemini с контролируемыми ответами.

`npm run build`: production-сборка React. Наличие тестов адаптера не означает выполненный запрос к реальному внешнему аккаунту.

## Что владелец подключает перед итоговой сдачей

1. SMTP отправителя, действительный APP_URL, затем проверить реальное письмо и папку «Спам».
2. Jamendo client ID — чтобы появился живой каталог и воспроизведение; Gemini API key и доступная модель — для разбора свободного описания.
3. Google Cloud project с billing/правами и домен → пройти DEPLOYMENT.md. Секреты не передавать через Git или скриншоты.
4. Сделать доказательства: публичный URL и VM, профиль до/после изменения, активация в почте, экран второго фактора, сохранение данных после перезапуска.

Нет оснований считать пункт IaaS выполненным, пока VM реально не развёрнута и публичный URL не проверен.
