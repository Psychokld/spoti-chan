# Техническое задание: Spoti-Chan v0.3

Дата: 31.10.2026. Учебное музыкальное веб-приложение с аккаунтами, подбором и каталогом. Документ заменяет ТЗ v0.2; состояние интеграций обозначается явно.

## 1. Назначение

Пользователь просматривает музыку, ищет по названию/исполнителю в текущем списке, вводит описание в Music Finder, сохраняет понравившиеся треки, получает рекомендации по тегам и слушает доступное аудио. Пример описания: «Что-то похожее на Linkin Park, но с женским вокалом».

Дизайн Chrome Edition: тёмный индиго, холодные синие/серебристые акценты, персонажи и хромовая композиция из пользовательских изображений. Иконка — первоначальный портрет. Слоган — «Красивая музыка / Красивые тян». Персонажи на карточках декоративные, не официальные обложки и не исполнители.

## 2. Объём и фактический статус

| Область | Реализовано | Требует внешнего подключения |
| --- | --- | --- |
| Frontend | React, Tailwind/CSS, Vite; каталог, Finder, избранное, аккаунт, диалог трека, аудиоплеер | Реальное аудио приходит из Jamendo |
| Backend | Express API, валидация, обработка ошибок, лимиты, same-origin защита, security headers | Публичный HTTPS origin |
| Аккаунты | Регистрация, активация, JWT-cookie, CRUD своего профиля, TOTP2FA и recovery codes | SMTP для настоящих писем; локальная запись письма не означает доставку |
| База | SQLite: пользователи, сессии, второй фактор, избранное | Постоянный том и backup при развёртывании |
| Музыка | Адаптер Jamendo, отображение режима, лицензий, ошибки, плеер | client ID, доступ к музыкальному API |
| ИИ | Адаптер Gemini: структурированные параметры, исключения, валидация ответа, поиск в каталоге | API key, доступная модель и квота |
| Рекомендации | Ранжирование по тегам первых 100 избранных, до 8 записей | Не являются обученной персональной моделью |
| IaaS | Docker, Compose, Caddy HTTPS, скрипты Google Compute Engine VM | **VM и публичный сайт пока не созданы**; аккаунт, billing, домен и проверка Docker обязательны |

Отсутствующие ключи оставляют явно обозначенный демокаталог и правила Finder. Ошибка уже настроенного внешнего сервиса не маскируется демонстрационным ответом.

## 3. Роли и навигация

- Гость: каталог, Finder, рекомендации, плеер при доступном аудио, локальное избранное, регистрация/вход.
- Неактивный пользователь: повторное письмо и подтверждение почты; вход в профиль запрещён.
- Активный пользователь: собственный профиль, серверное избранное и настройки 2FA. Просмотр/редактирование чужих пользователей не предусмотрены.

Разделы: `#/`, `#/finder`, `#/favorites`, `#/account`. Ссылка `#/verify?token=…` открывает явное подтверждение активации; одно посещение не расходует токен. После успеха токен убирается из URL. Мобильная навигация расположена снизу. Фокус видим, поля подписаны, состояния доступны вспомогательным технологиям.

## 4. Музыкальные сценарии

### Каталог и избранное

GET `/api/tracks` возвращает демонстрационные четыре записи либо до 40 записей Jamendo с кэшем 60 секунд. Поиск без учёта регистра фильтрует загруженный список по названию и исполнителю. Жанровый фильтр совмещается с поиском. У загрузки, ошибки с повтором и пустой выдачи разные состояния.

Карточка открывает диалог с метаданными, избранным и кнопкой прослушивания, если есть audioUrl. В противном случае указано отсутствие аудио; длительность и звук не выдумываются.

Избранное гостя хранится в localStorage для данного origin. После входа используется отдельная коллекция SQLite; гостевой список автоматически не присваивается аккаунту. Сохранение серверного избранного выполняется последовательными PUT-запросами, ошибки сообщаются. После выхода возвращается гостевой список. Для серверного избранного доступны до 500 идентификаторов. Выбранные записи подгружаются по ID, даже если их нет в первой странице каталога.

### Music Finder

Описание — непустая строка до 500 символов. Примеры заполняют поле, запрос отправляется кнопкой. При отправке предыдущий результат очищается, повтор блокируется. При ошибке текст сохраняется, сброс отменяет запрос. Уход со страницы отменяет запрос.

Без Gemini действует словарь жанров, четырёх демонстрационных исполнителей и типа вокала; сложные отрицания не поддерживаются. С Gemini извлекаются английские теги, исключённые теги, тип вокала и похожий исполнитель. Структура ответа проверяется. Сами названия песен и аудио из ответа модели не используются: результат выбирается из доступного каталога. При наличии Jamendo выполняется поиск с fuzzytags/gender/xartist, исключённые теги фильтруются. Акустическое совпадение или нахождение конкретной забытой песни не гарантируются.

Без Jamendo остаётся демокаталог без аудио. Его пример с Linkin Park и женским вокалом возвращает Going Under — Evanescence, затем Ice Queen — Within Temptation. Эти песни не гарантируются в реальном каталоге Jamendo.

### Плеер и рекомендации

Для Jamendo доступны native audio controls: Play/Pause, полоса прогресса, громкость. Выбор другого трека заменяет источник; закрытие останавливает компонент. Переход дальше использует воспроизводимые записи загруженного каталога. Ошибка источника и блокировка autoplay объясняются пользователю. Есть ссылки на Jamendo и лицензию; скачивание не предлагается.

Рекомендации запускаются кнопкой. Для избранных собираются музыкальные теги, уже сохранённые записи исключаются, результат сортируется по числу совпадений. Без предпочтений показывается стартовая подборка. Это отдельный алгоритм, не генеративная модель.

## 5. Аккаунты и безопасность

Регистрация требует имени 1–80 символов, email до 254 и пароля 12–128. Пароль хранится как scrypt с индивидуальной солью. Аккаунт до активации не входит. Токен почты случайный, хранится только SHA-256, срок 24 часа, применение одноразовое. Повторная отправка ограничена.

JWT HS256 содержит sub/jti, issuer/audience/expiration; хранится в HttpOnly/SameSite=Strict cookie, Secure в production. Сессия проверяется в SQLite, срок 2 часа. Выход отзывает текущую сессию; смена пароля/почты/2FA отзывает связанные сессии. JWT второго шага имеет отдельную audience и сам по себе не даёт доступ к профилю.

Чувствительные операции — новый пароль, почта, удаление аккаунта и управление 2FA — требуют текущего пароля; если 2FA включена, также нового TOTP или резервного кода. При смене почты аккаунт снова неактивен и требует подтверждения нового адреса. Даже при ошибке SMTP старый вход не восстанавливается автоматически.

TOTP: SHA1, 6 цифр, период 30 секунд, окно ±1. Настройка выдаёт QR и ручной ключ, действует 10 минут и включается после правильного кода. Повторный код отклоняется. Вход требует пароль, затем challengeToken и код; challenge действует 5 минут/5 попыток. Восемь резервных кодов хранятся хешированными, каждый одноразовый. Секреты TOTP шифруются AES-256-GCM ключом сервера. Секреты не коммитятся и не публикуются через API статических файлов.

Изменяющие запросы проверяют Origin и формат JSON; тела до 8 КБ. Есть ограничения количества запросов, Helmet и HTTPS-конфигурация. Лимиты рассчитаны на один процесс; распределённый rate limit, SSO, SMS, сброс забытого пароля и админ-панель в объём v0.3 не входят.

## 6. Данные и API

SQLite: users, sessions, login_challenges, recovery_codes, favorites; внешние ключи, каскадное удаление, WAL. Профиль содержит ID, email, displayName, emailVerified, twoFactorEnabled, createdAt. Хеши, JWT-secret и зашифрованные TOTP никогда не включаются в публичный профиль.

Трек: id, title, artist, vocals (female/male/unknown), tags; для Jamendo также audioUrl, duration, source/sourceUrl/licenseUrl; Finder добавляет matchedTags. Идентификаторы Jamendo имеют префикс jamendo:.

Полный перечень методов и полей — в README. Ключевые группы: `/api/auth/*`, `/api/users/me`, `/api/users/me/favorites`, `/api/tracks`, `/api/finder`, `/api/recommendations`, `/api/status`, `/api/health`. Ошибки имеют JSON `{error}` и соответствующий HTTP status. Неизвестный API-маршрут — 404 JSON.

## 7. Запуск, размещение и приёмка

Node.js 24+: `npm ci`, `npm run build`, `npm start`; разработка — `npm run dev`; проверки — `npm test`. APP_URL определяет ссылку активации. В разработке автоматически создаются локальные случайные секреты в игнорируемой `.data/`. Без SMTP письма сохраняются в `.data/outbox`, настоящей доставки нет. Production требует явных секретов, HTTPS APP_URL и SMTP. Конфигурация внешних сервисов — `.env.example`.

IaaS: Google Compute Engine Ubuntu VM, Docker app+Caddy, HTTPS, постоянный SQLite volume. Один reverse proxy, API-порт снаружи не публикуется. Точная процедура, backup и ограничения — `docs/DEPLOYMENT.md`. Docker в среде разработки отсутствовал: Linux-образ и живой облачный деплой должны быть проверены отдельно.

Критерии:

1. Установка по lock-файлу, тесты и сборка проходят.
2. Реальный пользователь сохраняется после перезапуска; без активации не входит; использованная/просроченная ссылка отклоняется.
3. JWT проверяется с сессией; чужой профиль недоступен; изменение имени, пароля/почты и удаление работают.
4. Включение 2FA, последующий вход, запрет повтора TOTP и одноразовость recovery code проверены.
5. Серверное избранное изолировано по пользователям; после выхода видно гостевое, без утечки чужой коллекции.
6. Finder выдаёт только каталожные записи; ошибки сервисов и пустые ответы различаются; деморежим честно обозначен.
7. С настроенным Jamendo играет реальное аудио, указаны источник и лицензия. С Gemini живой запрос проверяется отдельно после выдачи ключа.
8. Реальное письмо достигает Gmail после подключения SMTP, ссылка активирует аккаунт. Локального outbox для доказательства доставки недостаточно.
9. Все основные действия доступны с клавиатуры и на мобильной ширине без горизонтальной прокрутки.
10. Для закрытия IaaS требуется реально созданная VM, публичный HTTPS URL и сохранение данных после перезапуска. Одних файлов конфигурации недостаточно.
